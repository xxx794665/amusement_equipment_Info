# 上传即最终键（取消保存时转存）+ 图片栏位多图化

2026-11-03。取代 ADR-0003 中「保存时 CopyObject 转正式键」与「正式键内嵌设备 id」的部分。

## 背景

运营方两个诉求：

1. **建新设备失败率高**：旧流程选图先传临时键 `amusement/tmp/<随机>/<栏位>.<ext>`，保存时 Worker 串行执行 OSS CopyObject（临时键→正式键 `amusement/<设备id>/<栏位>.<ext>`）+ DELETE 临时键；新建设备还要先 INSERT 拿 id、转存完再 UPDATE 补图片字段。8 图 = 一次保存请求内串行 16 次跨区 fetch（CF Worker 海外节点 → 北京 OSS），每次 15s 超时上限，任一环慢即整次保存失败。
2. **图片栏位要多选多图**：旧模型每栏位恰一图（CONTEXT.md 原定义）。

## 决策

1. **上传即最终键，此后不改名**：选图时 Worker 直接按最终键签发预签名 URL（OSS）或经绑定直写（R2），键为 `amusement/<栏位>/<随机hex>.<扩展名>`；**不再内嵌设备 id**（新建设备时 id 尚不存在），**库内地址即最终地址，保存请求零存储操作**（只剩 D1 写入）。
2. **每栏位多图**：8 个图片列改存 JSON 数组字符串（如 `'["url1","url2"]'`，≤9 张）；**旧版单图记录保持纯 URL 字符串照读**，读取端 `parseStoredImages` 统一解析两种形态。展示页同栏位多图在同一标题下纵向堆叠，单图记录渲染结果与历史逐像素一致；首页列表缩略图取正视图第一张。
3. **删除清理改查库判归属**：键不再内嵌设备 id，原「只删本设备键前缀」守卫失效。删除对象前全表扫 8 列确认该 URL 全站无引用才删（设备量级小，成本可忽略），防跨设备复制 URL 误删。
4. **临时键机制整体下线**：`amusement/tmp/`、commit、discard-临时键全删；保存时显式拒绝残留 tmp 地址（提示重新选图，覆盖部署瞬间的旧会话窗口）。`POST /api/images/discard` 保留但语义改为「查库确认无引用才删」，管理端用于移除刚上传未保存的图。

## 后果

- 换图 = 新键新 URL（不再同键覆盖），浏览器/边缘缓存天然失效，旧对象按第 3 条清理；二维码指向展示页而非图片，不受影响。
- 上传后未保存就关页 → 留孤儿对象（与旧 tmp 机制同类，待办清理脚本不变，来源从「临时键」变为「未入库的最终键」）。
- 历史设备的旧键 `amusement/<设备id>/<栏位>.<ext>` 不迁移、照常读取与删除；两种键形的删除白名单并存。
- 已实测（生产）：直传、建档、双图堆叠、R2 路径、partial 更新不误伤、被移除对象 404 / 保留对象 200、discard 幂等且拒删已保存图、tmp 拒收、9 张上限、旧设备无回归。

## 落选方案

- **保留 id 内嵌键**：必须先建档拿 id 才能传图（新增流程改两步，交互倒退）或维持 tmp+转存（超时根源不除）。
- **关系表 device_images(device_id, slot, url, sort)**：模型更正但需 D1 迁移 + 全部读写路径改造，当前规模收益为零。
- **换图后不删旧对象**：最简单，但孤儿无限积累；查库成本极低，选精确清理。
